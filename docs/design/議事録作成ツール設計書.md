## 1. ツールの目的

会議の録音から、**人手で書いた議事録と同じ書式の Word 議事録を、事実に忠実に作る**こと。

| 項目     | 内容                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 使う人   | 議事録の記録者。<br />AI の出力を確認・修正して、最終成果物にする                                                          |
| 最優先   | **正しい事実としての議事録**。発言にないことを書かない。拾える発言は漏らさない<br />（具体例・経緯を本文で省かない） |
| 後回し   | 処理速度（漏れのない議事録ができてから検討。docs/issue/issue_md/ISSUE-018）                                                              |
| 守ること | **会議の音声はクラウドサービスに送らない**（文字起こし・話者分離はローカルで行う）                                   |
| 出力     | 人手版と同じ書式の Word（冒頭に会議情報の表、【決定事項】【TODO】【会議内容】）。<br />確認が必要な箇所は黄色の蛍光ペン    |

## 2. 動作環境

### 2.1 検証した環境

| 項目         | 内容                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| OS           | Windows 11 Home（10.0.26200）                                                    |
| CPU / GPU    | CPU 8スレッド、GPU なし                                                          |
| Python       | 3.12.10                                                                          |
| ffmpeg       | 不要（PyAV が音声をデコードする）                                                |

| ディスク     | モデル約1.7GB ＋ venv 2つで約3GB                                                 |
| ネットワーク | 初回のモデルのダウンロード（Hugging Face）と、議事録作成時の Claude との通信のみ |

### 2.2 Python 環境（venv を2つに分ける理由）

faster-whisper と pyannote は依存ライブラリ（numpy、huggingface_hub、torch）のバージョンが衝突するため、venv を分けている。

| venv           | 用途                                                            | 主なパッケージ                                                                                                                      | 一覧                         |
| -------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `.venv`      | 文字起こし、抜けの補完、自己点検、Word 出力、Issue 一覧、用語集 | faster-whisper 1.2.1、ctranslate2 4.9.1、av 19.0.2、numpy 2.5.5、python-docx 1.2.0、openpyxl 3.1.5、pypdfium2・pillow（PDF 確認用） | `requirements-whisper.txt` |
| `.venv-diar` | 話者分離                                                        | pyannote.audio 3.3.2、torch 2.5.1+cpu、torchaudio 2.5.1+cpu、numpy 1.26.4、huggingface_hub 0.25.2、lightning 2.4.0、av 19.0.2       | `requirements-diar.txt`    |

**バージョン固定が必要な理由（実際に起きた不具合）**

- pyannote.audio 3.3.2 は、torchaudio 2.9 以降で `AttributeError: torchaudio.AudioMetaData` になる → torch / torchaudio を 2.5.1 に固定。
- pyannote.audio 3.3.2 は `use_auth_token` 引数を使うため、huggingface_hub 1.0 以降では動かない → 0.25 系に固定。
- pyannote の依存（pyannote.core など）は新しいメジャー版と互換性がない → 5.0.0 などに固定。
- PyAV 19 では faster-whisper 内蔵の音声読み込みが失敗する → 音声は自前の `src/audio_io.py` で読み込み、配列で渡す。

### 2.4 導入手順（新しい環境）

```powershell
# 0. フォルダ一式をコピー（.venv / .venv-diar はコピーせず作り直す）
cd 20261122_Voice_Translate_2

# 1. 文字起こし用 venv
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install -r requirements-whisper.txt

# 2. 話者分離用 venv（torch は CPU 版の配布元を指定する）
py -3.12 -m venv .venv-diar
.venv-diar\Scripts\python -m pip install --upgrade pip
.venv-diar\Scripts\python -m pip install -r requirements-diar.txt --extra-index-url https://download.pytorch.org/whl/cpu

# 3. Hugging Face の準備（初回のみ）
#    (a) https://huggingface.co/pyannote/speaker-diarization-3.1 と
#        https://huggingface.co/pyannote/segmentation-3.0 で「Agree」を押す
#    (b) https://huggingface.co/settings/tokens で Read 権限のトークンを作る
#    (c) トークンを保存（~/.cache/huggingface/token に保存される）
.venv-diar\Scripts\python -c "from huggingface_hub import login; login()"
```

- モデルは初回実行時に自動でダウンロードされる。Hugging Face に接続できない環境では、接続できる PC で `~/.cache/huggingface/hub/` と `~/.cache/torch/pyannote/` を作ってからコピーする。
- 日本語を含むパスで動かすため、実行時は `PYTHONUTF8=1` を設定する（一括実行スクリプトは自動で設定する）。
- 一括実行スクリプトは実行中のスリープを抑止するが、蓋を閉じた時の動作は電源設定に従う。長時間の処理中は蓋を閉じない。

### 2.5 ガードレール（音声をクラウドに送らない）

- `test_code/.claude/hooks/block-audio-upload.ps1`（Claude Code の PreToolUse フック）が、次の操作を拒否する。
  - Bash / PowerShell：音声・動画ファイル（.m4a、.mp3、.wav、.mp4 など）と、通信のコマンド（curl、Invoke-WebRequest、scp、aws s3、azcopy、requests.post、git push、https:// など）が同じコマンドに含まれる場合
  - WebFetch / WebSearch / MCP ツール：入力に音声・動画ファイル名が含まれる場合
- 登録先：`test_code/.claude/settings.json`（test_code を開いた場合）と `20261122_Voice_Translate_2/.claude/settings.json`（プロジェクトを直接開いた場合）。Claude Code の再起動後に有効。
- 限界：ソフトウェア上のガードレールで、OS レベルの遮断ではない。人が手で実行するコマンドは止められない。ツールのコードは音声を外部に送る処理を持たない。
- 議事録作成（4章の④）では、**文字起こしのテキスト**を Anthropic（Claude）に送る。音声は送らない。

## 5. 処理の詳細

### 5.1 ①〜③ 一括実行 `src/run_pipeline.py`

```powershell
.venv\Scripts\python src\run_pipeline.py INPUT\<名前>.m4a --speakers <参加人数>
```

- ①②③を順に実行し、工程ごとの開始・終了時刻と処理時間を `transcripts/<名前>/<名前>.timing.json` に記録する。
- 実行中は Windows のアイドル時スリープを抑止する。
- 工程を個別に実行する場合は 5.2〜5.4 のコマンドを使う。
- **入力は3通り**（docs/issue/issue_md/ISSUE-002）。音声とテキストは同じ名前（拡張子だけ違う）で `input/` に置くと自動で組み合わせる。`--text` で明示もできる。
- **入力の種類は、ファイル名から自動で判定する**（`run_pipeline.py` の `main` / `find_pair`）。`input/` フォルダ全体を見回すのではなく、コマンドに渡した1つのファイルを起点に、次の手順で決める。
  1. 渡したファイルの拡張子で、音声かテキストかを決める。
     - 音声：`.m4a` `.mp3` `.wav` `.mp4` `.aac` `.flac` `.ogg` `.webm` `.mov`
     - テキスト：`.vtt` `.docx` `.txt` `.md`
  2. 同じフォルダに、**同じ名前で拡張子だけ違う**もう一方の種類のファイルがあるかを探す（例：`20261120_CI.m4a` に対して `20261120_CI.vtt`）。会議情報ファイル（`<名前>.会議情報.txt`）は名前が違うので対象にならない。
  3. 両方あれば「テキスト＋音声」、音声だけなら「音声のみ」、テキストだけなら「テキストのみ」。`--text` で指定した場合は、そのテキストを組み合わせる。
  - 判定の結果は、実行時に「入力：テキスト＋音声（音声：…、テキスト：…）」と表示し、`.timing.json` の `mode` に記録する。
  - テキストの形式（Teams の `.vtt` / `.docx`、Notion などの `.txt` / `.md`）は、`src/import_text.py` が中身から自動判定する。

| 入力 | 工程 | 話者名 |
|---|---|---|
| 音声のみ（話者分離する） | ① → ② → ③ | ②の話者記号＋会議情報ファイルの話者対応表 |
| 音声のみ（話者分離しない） | ① → ③（VAD あり） | 議事録作成（④）で Claude が内容から推定 |
| テキストのみ（Teams `.vtt` / `.docx`、Notion `.txt` / `.md`） | テキストの取り込み（`src/import_text.py import --text-only`） | テキストの話者名 |
| テキスト＋音声 | ①（既存の `.srt` があれば再利用）→ ③（VAD あり）→ テキストの取り込み → 話者の対応付け（`src/import_text.py align`：時刻の重なりでテキストの話者名を付ける） | テキストの話者名（②は不要） |

  - テキストの話者名は、会議情報ファイルの参加者欄が空欄なら自動で入る。
  - 「音声のみ」で処理済みの会議にテキストを足した場合は、`<名前>_テキスト併用` に出力して上書きしない。
  - テキストの読み込み結果は `<名前>.text.json`・`<名前>.text.txt`。議事録作成では `.text.txt` も読み、本文を突き合わせる（作成ルール14）。
- **②話者分離を行うかの設定**（docs/issue/issue_md/ISSUE-024）
  - 次の順で決まる（`src/setting.py` の `diarize_enabled`）。
    1. コマンドの `--no-diarize`（検証用）
    2. 会議情報ファイルの `話者分離:` 欄（する / しない）
    3. `setting/setting.xlsx` の「話者分離（pyannote）を行う」（既定は **しない**）
  - 決まった結果と理由は、実行時に表示し、`.timing.json` の `diarize`・`diarize_reason` に記録する。
  - 「しない」の場合は ①→③ だけを行い、③は区間全体を VAD ありで再文字起こしする。出力先は次のとおり。
    - `--no-diarize` を付けた場合、または話者分離済みの結果（`.diarization.json`）が既にある会議：`transcripts/<名前>_話者分離なし/` に分け、通常の結果を上書きしない。
    - それ以外：通常の `transcripts/<名前>/`。
  - 話者は議事録作成（④）で Claude が内容から判断する（docs/issue/issue_md/ISSUE-022）。
- **Whisper に用語集を渡すかの設定**（docs/issue/issue_md/ISSUE-025）
  - ①文字起こしと③抜けの補完で、参加者名と用語集の語を Whisper のヒント（`hotwords`）として渡す。社内用語・人名の誤変換を減らすため。
  - 次の順で決まる（`src/setting.py` の `whisper_hotwords`）。
    1. 会議情報ファイルの `Whisperに用語集を渡す:` 欄（渡す / 渡さない）
    2. `setting/setting.xlsx` の「文字起こし」シートの「Whisper に用語集を渡す」（既定は **渡す**）
  - 渡す語は、参加者名 → 会議情報ファイルの `Whisperに渡す追加の語:` → 用語集の「確認済」の語（誤変換例の多い順）の順に、「渡す語の上限（文字数）」（既定120字。Whisper の上限はおよそ100〜150字）まで入れる。
  - 渡した語と理由は、実行時に表示し、`.timing.json` の `hotwords` と `.meta.json` の `hotwords` に記録する（処理時間への影響を比べるため）。
  - 懸念：処理が遅くなる可能性、話していない語を作り出すおそれ。CI で効果と副作用を確かめてから既定値を見直す。

### 5.2 ① 文字起こし `src/transcribe.py`

```powershell
$env:PYTHONUTF8=1; .venv\Scripts\python src\transcribe.py INPUT\<名前>.m4a
```

| 設定                       | 値             | 理由                                           |
| -------------------------- | -------------- | ---------------------------------------------- |
| model                      | large-v3-turbo | CPU でも実用的な速度で、日本語の精度が高い     |
| device / compute_type      | cpu / int8     | GPU なし。int8 で速度とメモリを節約            |
| language                   | ja             | 言語の自動判定を省く                           |
| beam_size                  | 5              | 標準値                                         |
| vad_filter                 | True           | 無音区間を飛ばして速くする                     |
| condition_on_previous_text | False          | 長い音声で同じ文を繰り返す誤動作（幻覚）を防ぐ |

- 音声は `src/audio_io.py` で 16kHz モノラル float32 に変換してから渡す。
- 出力：`.txt`（[時刻] テキスト）、`.json`（セグメント）、`.srt`、`.meta.json`（設定・処理時間）。

### 5.3 ② 話者分離 `src/diarize.py`

```powershell
$env:PYTHONUTF8=1; .venv-diar\Scripts\python src\diarize.py INPUT\<名前>.m4a --speakers <参加人数>
```

- pyannote 3.1（CPU）で話者区間を求め、`.diarization.json` に保存する。
- `--speakers` に参加人数を指定する（指定しないと自動推定）。
- Whisper の各セグメントに、時間の重なりが最も大きい話者を割り当てる（`src/merge_speakers.py`）。同じ話者が続く行はまとめて `.speakers.txt` に出力する。
- 出力の話者は `SPEAKER_00` などの記号。**氏名との対応表は人が作る**（ヒアリング形式では AI の推定が誤った。docs/issue/issue_md/ISSUE-001）。
- 既知の限界：声の近い2人を1人と判定することがある（CI でGさん・Eさんが同じ記号になった）。
- **pyannote が議事録の精度に効く会議・効かない会議**（2026/11/23 の検証。docs/issue/issue_md/ISSUE-024）
  - 同じ文字起こしから議事録を作り、人手版と発言者を照合した。

| 会議の性質 | pyannote なし（Claude が内容から推定） | pyannote あり＋人が確かめた話者対応表 | 結論 |
|---|---|---|---|
| ヒアリングのように自由に発言する会議で、聞き手（質問する側）が複数いる（Bさんヒアリング、6人） | 話者誤り 21.2% | 話者誤り 2.0%（人手版側が疑わしい2件を除けば 0%） | **pyannote を使うと精度が上がる** |
| 司会が順に指名する会議（CI、5人） | 話者誤り 0件 | 話者誤り 0件 | pyannote がなくても精度は変わらない |

  - 内容からの推定では、立場の似た聞き手どうし（質問する人が複数いる場合）や、名前で呼ばれない参加者を区別できない。pyannote は声で発言を分けるので、この弱点を補える。
  - ただし、話者記号と氏名の対応表を AI の推定だけで作ると、1か所の取り違えで1人分の発言がすべて誤る（AI 推定の対応表では 20.3%）。pyannote を使うときは、対応表を人が確かめる。
  - pyannote の発話区間は③抜けの補完にも使っている。CI では、pyannote なしだと補完で戻る文字が 1/10 になった（+388字 → +38字）。

### 5.4 ③ 抜けの補完 `src/fill_gaps.py`

```powershell
$env:PYTHONUTF8=1; .venv\Scripts\python src\fill_gaps.py INPUT\<名前>.m4a
```

Whisper が長い発言を数文字に潰す不具合への対策（docs/issue/issue_md/ISSUE-011）。CI では約70秒の報告が「承知です。」の5文字になっていた。

| 検出の条件                                                                                | 処理                                                                       |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 10秒以上のセグメントで、1秒あたり1.5字未満（通常の発話は5〜8字/秒）                       | pyannote が発話を検出した部分だけを VAD なしで文字起こしし直し、置き換える |
| pyannote が3秒以上の発話を検出しているのに、Whisper のセグメントが20%未満しか覆っていない | 同様に文字起こしして追加する                                               |

補完した区間は `.meta.json` の `gap_fill` に記録し、話者を割り当て直して `.speakers.txt` を作り直す。

### 5.5 ④ 議事録の作成（Claude）

**現状**：議事録作成スキル（`.claude/skills/minutes/SKILL.md`）の手順に沿って、Claude Code の中で Claude が `.speakers.txt` を読んで md を書く。**作成ルールの正本はスキルの `references/writing-rules.md`**。以下はその要約。

話者対応表は `src/speaker_samples.py` で話者ごとの発言例を出し、記録者が決める。用語集は `src/glossary_tool.py dump` で読み出して参照する。

**入力**

1. `transcripts/<名前>/<名前>.speakers.txt`
2. 会議情報ファイル `INPUT/<名前>.会議情報.txt`（記録者が議事録作成の前に記入。`src/meeting_info.py init` でひな形を作る）
   - 会議名（記録者が決める。ルールなし。既定値は入力ファイル名＝音声ファイル名、テキスト入力ならテキストファイル名）、日時、場所、会議の種類（チェックイン / ヒアリング / その他）、記録者、参加者、資料
   - `[話者対応表]`：`SPEAKER_00: 氏名`。空欄なら Claude が発言例から推定して「（AI推定）」付きで書き込み、該当の発言に【推定】を付ける
   - 予定表とは連携しない
3. 参加者・関係者の所属と名簿（用語集の「人名」シート）。名簿にない・表記が確かでない人名は `氏名【要確認：人名】` として残し、記録者が最後に直す
4. 用語集（「用語」シート：正式表記・誤変換例）

**作成ルール**（検証計画 3.3 と Issue の決定事項）

| No. | ルール                                                                                                                                                                                                     | 根拠           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| 1   | 発言にないことは書かない                                                                                                                                                                                   | 検証計画 3.3   |
| 2   | 確度は語尾で書き分け、発言より強く書かない                                                                                                                                                                 | 検証計画 3.3   |
| 3   | 文字起こしにない語に直した箇所は【推定：元の語】、聞き取れない箇所は【聞き取り不明：元の語】、確認が必要な箇所は【要確認：内容】。**印を付けずに言い換えない**。崩れた箇所も飛ばさずに印を付けて残す | ISSUE-014・015 |
| 4   | **拾えるものはすべて拾う**。省略の判断は記録者が行う                                                                                                                                                 | ISSUE-004・011 |
| 5   | **質問と回答は対で残す**。質問を回答側の説明に盛り込んでもよいが、情報を落とさない                                                                                                                   | ISSUE-015      |
| 6   | **本文では具体例・経緯を省かない**（決定事項・TODO では要約してよい）                                                                                                                                | ISSUE-015      |
| 7   | 話し言葉の崩れた語順は、意味を変えずに書き言葉に整える（主語を前、述語を後）                                                                                                                               | ISSUE-003・010 |
| 8   | 用語・人名は用語集の正式表記で書く                                                                                                                                                                         | ISSUE-005      |
| 9   | 画面共有された資料の位置に `[(画像内容名)]` の枠を置く                                                                                                                                                   | ISSUE-013      |
| 10  | 冒頭に【決定事項】【TODO】（担当・期限）をまとめる                                                                                                                                                         | ISSUE-009      |

**見出しの付け方**（人手版の2会議から読み取った規則。会議の種類は Claude が冒頭のやり取りから判断する）

| 会議の種類 | 見分け方 | 見出しの形 | 区切り方 |
|---|---|---|---|
| チェックイン形式（CI など） | 司会が「〇〇さんお願いします」と順に指名する | `〇〇さんの会議/議題名` | 指名された人ごとに区切り、その人の報告の中で話題（予定・タスク・相談事項）が変わるところでさらに区切る。質疑はその話題の見出しの下に入れる。全員向けの連絡は `全体/…` |
| ヒアリング形式 | 聞き手が質問し、相手が業務を説明する | `取引先・対象/区分：内容` | 聞き手の新しい質問、「最後に取引先Q…」などの話題の切り替え、画面共有の開始で区切る。取引先・対象（取引先P、取引先R、取引先Qなど）が変わったら見出しの前半を変える |

ヒアリング形式の区分は、その見出しの中のやり取りの性質で決める。

| 区分 | 使う場面 |
|---|---|
| 確認 | 業務の内容・流れ・仕組みを質問して確かめるやり取り |
| 課題 | 話し手が困っていること、手間・不具合が起きていること |
| 懸念 | まだ起きていない、または起きているか分からないが、問題になりうること |
| 活動 | 話し手が行った取り組み（提案など） |
| コメント | 聞き手側の意見・所感・今後の方針 |

- 見出しの「議題名・内容」は、その区切りの中の発言から作る。発言にない言葉で見出しを作らない。
- 見出しの付け方は Claude の判断によるため、同じ会議でも作るたびに区切りが変わる可能性がある（ISSUE-003）。

| 資料 | |

- 決定事項。(発言者)

## 取引先P/確認：内容               ← ヒアリング形式（区分：確認・課題・懸念・活動・コメント）

### 5.10 設定条件の一覧

処理の設定は4か所にある。**同じ項目が複数の場所にある場合は、上ほど優先される。**

| 優先 | 場所 | 誰が変えるか | 範囲 |
|---|---|---|---|
| 1 | コマンドの引数（例：`--no-diarize`） | 検証・個別の実行 | その実行だけ |
| 2 | 会議情報ファイル `input/<名前>.会議情報.txt` | 記録者 | その会議だけ |
| 3 | `setting/setting.xlsx` | 記録者 | すべての会議の既定値 |
| 4 | コードの中の既定値（`src/*.py`） | 開発者（コードの修正が必要） | すべての会議 |

`setting.xlsx` は「設定値」の列だけを変える（「キー」の列はプログラムが項目を見分けるのに使う）。空欄、またはファイルがない場合はコードの既定値で動く。保存してから処理を始める（`src/setting.py` が読み込む）。

#### (1) `setting/setting.xlsx`（すべての会議の既定値）

| シート | キー | 項目 | 既定値 | 入力できる値 | 会議ごとの上書き | 関連 |
|---|---|---|---|---|---|---|
| 文字起こし | `whisper_glossary` | Whisper に用語集を渡す | 渡す | 渡す / 渡さない | 会議情報ファイル `Whisperに用語集を渡す:` | ISSUE-025、5.1 |
| 文字起こし | `whisper_glossary_max_chars` | 渡す語の上限（文字数） | 120 | 20〜200 | なし | ISSUE-025 |
| 話者分離 | `diar_enabled` | 話者分離（pyannote）を行う | しない | する / しない | 会議情報ファイル `話者分離:`、コマンド `--no-diarize` | ISSUE-024、5.1 |
| 話者分離 | `diar_shift_sec` | 窓のずらし幅（秒） | 2.0 | 0.5〜5.0 | なし | ISSUE-018（1.0 比で約2倍速・一致率98.1%。3.0以上は精度が大きく落ちる） |
| 話者分離 | `diar_min_cluster_size` | 1話者あたりの最低特徴量数 | 自動 | 「自動」または2以上の整数 | なし | ISSUE-018 |

#### (2) 会議情報ファイル `input/<名前>.会議情報.txt`（その会議だけ）

記入の仕方は 6.3。処理の設定に関わる欄は次のとおり。

| 欄 | 使う工程 | 空欄の場合 |
|---|---|---|
| 会議名 | ⑥ Word の題名 | 入力ファイル名 |
| 会議の種類（チェックイン / ヒアリング / その他） | ④ 見出しの付け方、⑥ テンプレートの選択 | Claude が冒頭のやり取りから判断 |
| 参加者 | ④ 発言者、Whisper に渡す語の先頭 | テキスト入力なら話者名が自動で入る |
| 話者分離（する / しない） | ② | `setting.xlsx` の `diar_enabled` |
| Whisperに用語集を渡す（渡す / 渡さない） | ①③ | `setting.xlsx` の `whisper_glossary` |
| Whisperに渡す追加の語 | ①③（参加者名の次に渡す） | 渡さない |
| `[話者対応表]`（`SPEAKER_00: 氏名`） | ④ 発言者 | Claude が推定して【推定】を付ける |

## 6. ツール実行手順

会議1件ごとの手順。初めて使う PC では、先に 2.4 の導入手順を済ませておく。

### 6.1 全体の流れ

| 順 | 誰が | 何をする | 出力 |
|---|---|---|---|
| 1 | 記録者 | 入力ファイルを `input/` に置く | — |
| 2 | 記録者 | 会議情報ファイルを記入する | `input/<名前>.会議情報.txt` |
| 3 | 記録者 または Claude | ①〜③ 文字起こし・話者分離・抜けの補完を実行する | `transcripts/<名前>/` |
| 4 | Claude | ④〜⑦ 議事録の作成・自己点検・Word 出力・用語集の候補 | `output_MeetingMinutes/<名前>/` |
| 5 | 記録者 | Word を確認・修正し、用語集の候補を確認する | 完成した議事録、用語集 |

### 6.2 手順1：入力ファイルを置く

- `input/` に会議の録音・文字起こしテキストを置く。**音声とテキストを組み合わせる場合は、同じ名前（拡張子だけ違う）にする**（5.1 の自動判定）。

| 入力 | 置くもの（例） |
|---|---|
| 音声のみ | `input/20261201_定例.m4a` |
| テキストのみ | `input/20261201_定例.vtt`（Teams）、`.docx`（Teams）、`.txt` / `.md`（Notion など） |
| テキスト＋音声 | `input/20261201_定例.m4a` と `input/20261201_定例.vtt` |

- ファイル名の先頭に日付（`YYYYMMDD`）を付けると、会議情報ファイルの日付・曜日が自動で入る。
- 音声ファイルは GitHub やクラウドに上げない（2.5、`.gitignore`）。

### 6.3 手順2：会議情報ファイルを記入する

ひな形を作る（Claude に頼んだ場合は Claude が作る）。

```powershell
.venv\Scripts\python src\meeting_info.py init input\<名前>.m4a --participants 氏名,氏名
```

| 欄 | 記入すること | 空欄の場合 |
|---|---|---|
| 会議名 | 議事録の題名 | 入力ファイル名 |
| 日時・場所・資料 | 分かる範囲で | 議事録でも空欄 |
| 会議の種類 | チェックイン / ヒアリング / その他（Word の書式が変わる） | Claude が冒頭のやり取りから判断 |
| 記録者・参加者 | 氏名（所属は用語集の「人名」シートから付く） | テキスト入力なら話者名が自動で入る |
| 話者分離 | この会議だけ変えるときに する / しない | `setting/setting.xlsx` の設定 |
| Whisperに用語集を渡す | この会議だけ変えるときに 渡す / 渡さない | `setting/setting.xlsx` の設定 |
| Whisperに渡す追加の語 | この会議で出そうな固有名詞（「、」区切り） | 渡さない |
| `[話者対応表]` | `SPEAKER_00: 氏名`（話者分離の後に分かれば） | Claude が推定し【推定】を付ける |

- 処理の既定値（話者分離の有無、Whisper に用語集を渡すか、話者分離の設定など）は `setting/setting.xlsx` で変える。保存してから処理を始める。設定の全体と優先順位は 5.10。

### 6.4 手順3〜4：実行する

実行のしかたは2通り。**④議事録の本文を書く工程は Claude が行う**ので、どちらの場合も最後は Claude Code に頼む。

**方法A：Claude Code にすべて頼む（通常）**

1. `20261122_Voice_Translate_2` のフォルダを開いて Claude Code を起動する（議事録作成スキルと音声送信禁止フックが有効になる）。
2. 「`input/<名前>.m4a` から議事録を作って」と頼む。
3. Claude が議事録作成スキル（`.claude/skills/minutes/SKILL.md`）の手順で ①〜⑦ を進める。途中で、会議情報ファイルの記入や話者の確認を頼まれたら答える。

**方法B：時間のかかる①〜③を自分で実行し、④以降を Claude に頼む**

夜間にまとめて処理しておきたい場合など。

```powershell
cd <20261122_Voice_Translate_2 のフォルダ>
.venv\Scripts\python src\run_pipeline.py input\<名前>.m4a     # 音声（同名のテキストがあれば テキスト＋音声）
.venv\Scripts\python src\run_pipeline.py input\<名前>.vtt     # テキストのみ
```

- 処理時間の目安は 7章（CPU のみで音声の数倍。話者分離をしなければ短い）。実行中は PC をスリープさせない（蓋を閉じない）。
- 終わったら Claude Code に「`<名前>` の議事録を作って」と頼む。文字起こしはやり直さず、④から進む。

### 6.5 手順5：確認する

1. `output_MeetingMinutes/<名前>/<名前>_議事録.docx`（2回目以降は `_Ver2.0`、`_Ver3.0` …）を開く。既存の Word は消えず、上書きもされない。
2. 黄色の【推定】【聞き取り不明】【要確認】の箇所を、必要に応じて音声で確かめて直す。
3. 用語集（`docs/design/議事録作成用の用語集.xlsx`）の「候補」シートで、Claude の推奨を見て「登録先」を決める。登録は Claude に頼む。
4. 検証として人手版と比べる場合は、Word ができた後に人手版を Claude に渡す（`verification` スキルで結果を記録する）。

### 6.6 コマンド一覧

| 目的 | コマンド（プロジェクトのフォルダで実行） | 主に使う人 |

### 6.7 困ったとき

| 症状 | 対処 |
|---|---|
| 処理が途中で止まった・異常に遅い | PC のスリープを確認する。`transcripts/<名前>/<名前>.timing.json` で止まった工程を確かめ、`run_pipeline.py` を実行し直す |
| Word・Excel の保存に失敗する（Permission denied） | そのファイルを Excel・Word で開いていないか確認し、閉じてから実行し直す |
| 話者がほとんど1人にまとめられた | 会議情報ファイルの `[話者対応表]` を確認する。2名の会議などでは「話者分離: しない」にして、Claude の内容判断に任せる（docs/issue/issue_md/ISSUE-022・024） |
| 「おやすみなさい」など話していない文が出る | 無音区間の幻覚（docs/issue/issue_md/ISSUE-021）。議事録では本文から外して注記される |
| 社内用語・人名の誤変換が多い | 用語集に正式表記と誤変換例を登録する。会議情報ファイルの「Whisperに渡す追加の語」に書く |
