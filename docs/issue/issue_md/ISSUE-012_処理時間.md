# ISSUE-012 処理時間（CPU だけでは会議の数倍かかる）

| 項目 | 内容 |
|---|---|
| 区分 | 論点 |
| 状態 | 済 |
| 起票日 | 2026/11/23 |
| 対象会議 | 11/20 CI、11/20 Bさんヒアリング |
| 関連 | ISSUE-001、ISSUE-002、ISSUE-011 |

## 何が起きているか・何が分からないか

今の PC（GPU なし、CPU 8スレッド）では、文字起こしと話者分離に会議時間の数倍かかる。1時間の会議だと、議事録の下書きが出るまでに半日近くかかる可能性がある。

## 根拠

| 工程 | CI（音声 28分） | Bさんヒアリング（音声 63分） |
|---|---|---|
| 文字起こし（Whisper） | 40分（音声の1.4倍） | 101分（1.6倍） |
| 話者分離（pyannote） | 80分（2.8倍） | 約5.9時間（5.6倍。スリープで止まっていた約7.5時間を除く） |
| 抜けの補完 | 数分 | 数分 |
| 議事録案の作成（Claude） | 約15〜20分（話者の対応付け・抜けの調査を含む） | 約15分（話者の対応付けを含む） |

※文字起こしと話者分離を同時に動かしていたため、単独で動かした場合より遅くなっている。

Bさんヒアリングの話者分離は、単独で動かしても約5.9時間（スリープ時間を除く。音声の5.6倍）かかった。CI（2.8倍）より大幅に遅く、音声が長いほど不利になる可能性がある。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | 今の構成のまま、夜間にまとめて処理する | 追加費用なし。音声を外に出さない | 翌日まで待つ。スリープ対策が必要 |
| B | GPU のある PC・サーバーで処理する | 10倍以上速くなる見込み | 機材の用意が必要 |
| C | クラウドの文字起こし（Azure Speech、OpenAI など。話者分離付き） | 速い。話者分離も付く | 音声を社外に送る。社内ルールの確認が必要。費用 |
| D | Teams の文字起こしを使う（ISSUE-002） | 処理がほぼ不要。話者名付き | Teams 会議でしか使えない |
| E | 軽いモデルや設定にする（モデルを小さくする、話者分離を省く） | 速くなる | 精度が落ちる |

## 不明点（Aさんに確認したい）

1. 議事録は会議後どれくらいで欲しいか（当日中 / 翌日でよい）。
2. 会議の音声を社外のクラウドサービスに送ってよいか（社内ルール）。

## ソフトへの影響

処理の実行場所（ローカル / GPU サーバー / クラウド）が決まる。ソフト全体の構成に関わる。

## 決定内容

2026/11/23 Aさん：- 議事録は、できれば当日中に欲しいが、そこまで急ぎではない。
- スピードアップの方法は、今後の課題として別途検討する → ISSUE-018。
- **音声はクラウドサービスに絶対に送らない。**
- 対応：音声・動画ファイルを外部に送る操作を拒否するフック `test_code/.claude/hooks/block-audio-upload.ps1` を作成し、`test_code/.claude/settings.json` とプロジェクトの `.claude/settings.json` に登録した（Claude Code の再起動後に有効）。案 C（クラウドの文字起こし）は不採用。
