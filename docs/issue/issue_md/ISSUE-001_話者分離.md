# ISSUE-001 話者分離をどう行うか

| 項目 | 内容 |
|---|---|
| 区分 | 論点 |
| 状態 | 済 |
| 起票日 | 2026/11/22 |
| 対象会議 | 11/20 CI、11/20 Bさんヒアリング |
| 関連 | 検証計画 4.3「話者誤り」、ISSUE-002 |

## 何が起きているか・何が分からないか

Whisper の文字起こしには発言者が付かない。発言者が分からないと、議事録に「誰が言ったか」を書けず、検証計画の指標「話者誤り」も評価できない。

## 根拠

- faster-whisper の出力はテキストとタイムスタンプだけ。
- 議事録では「〇〇さんの認識」「〇〇さんより」のように、発言者で確度を書き分ける（検証計画 3.3）。

### 11/20 CI での結果（2026/11/23 追記）

- pyannote 3.1（参加者数5を指定）で話者記号を付けた。CPU で約80分（文字起こしと並行実行）。
- 対応付けは、司会が「〇〇さんお願いします」と指名した直後の話者から Claude が推定した。

| 記号 | 推定 | 結果 |
|---|---|---|
| SPEAKER_01 | Cさん | R と一致 |
| SPEAKER_02 | Aさん | R と一致 |
| SPEAKER_04 | Dさん | R と一致 |
| SPEAKER_03 | Eさん＋Gさん | **2名が1人と判定された**。Claude が発言内容から振り分け、結果は R と一致 |
| SPEAKER_00 | — | 合計8秒の雑音程度 |

- 1行の中に別の人の相づち・短い発言が混ざる箇所がある（例：06:14 前後）。
- 分かったこと：チェックインのように司会が順に指名する会議なら、氏名の対応付けは Claude が十分できる。ヒアリングのように自由に話す会議でどうなるかは、Bさんヒアリングで確認する。

### 11/20 Bさんヒアリングでの結果（2026/11/23 追記）

- pyannote 3.1（参加者数6を指定）。CPU で約5.9時間（スリープ時間を除く）。
- ヒアリングは司会が順に指名しないので、名前で呼ばれた箇所から推定するしかなかった。

| 記号 | 推定 | R での実際 |
|---|---|---|
| SPEAKER_05 | Bさん | 一致 |
| SPEAKER_02 | Aさん【推定】 | 一致 |
| SPEAKER_01 | Hさん【推定】 | 一致 |
| SPEAKER_04 | 司会（IさんかFさん） | Iさん |
| SPEAKER_03 | Dさん【推定】 | **Fさん（13発言で話者誤り）** |
| SPEAKER_00 | 不明 | 不明（R にDさんの発言はない） |

- 誤りの原因：54:11「Fさんは大丈夫ですか」を「Dさん」と推定したが、「Fさん」だったと思われる。1か所の聞き違いで1人分の発言がすべて誤った。
- 分かったこと：**ヒアリング形式では、話者記号と氏名の対応付けを AI だけでは決められない。** 人が冒頭の数分を聞いて対応表を作るか、声の登録（話者照合）が必要。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | pyannote で話者分離し、Whisper の結果と時刻で突き合わせる | 精度が高い。ローカルで動き、音声を外に出さない | Hugging Face のトークンと利用規約への同意が必要。CPU では時間がかかる。出力は SPEAKER_00 などの記号で、氏名との対応は人か Claude が付ける |
| B | Teams の文字起こし（話者付き）を使う | 話者名が最初から付いている | 録音しかない会議には使えない（ISSUE-002） |
| C | 話者なしで Claude に文脈から推定させる | 追加ツールが不要 | 推定を誤ると話者誤りになる。検証の公平性が下がる |

## ソフトへの影響

- A の場合：文字起こし → 話者分離 → 突き合わせ → 話者記号を氏名に置き換え、の4段構成になる。
- 「SPEAKER_00 = Bさん」の対応付けを誰がどうやるか（人が冒頭を聞いて指定する / Claude が自己紹介などから推定する）を決める必要がある。

## 決定内容

2026/11/22 Aさん：今の PC で動くなら A（pyannote）を試す。対応付けの方法は未定。

2026/11/23 Aさん：話者対応表は設定ファイルに置き、あればそれを読み込む。なければ議事録作成の前に AI が読む（推定する）運用にする。
- 対応：会議情報ファイル `INPUT/<名前>.会議情報.txt` の `[話者対応表]` 欄（`SPEAKER_00: 氏名`）を作成（`src/meeting_info.py`）。記入があればそれを使い、空欄なら Claude が `src/speaker_samples.py` の発言例から推定して「（AI推定）」付きで書き込み、該当の発言に【推定】を付ける。議事録作成スキル手順2に反映。
