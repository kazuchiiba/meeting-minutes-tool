## 何が起きているか・何が分からないか

R は業務上の論点に絞って約2,000字、C はほぼ全発言を書いて約5,500字になった。R に書かれた議題はすべて C にもあるが、R が省いたものも C には書かれている。何を省くかの基準が分からないと、ソフトは R の分量に近づけない。

## 根拠

R が省いていて C には書いてあるもの：
- 記録者（Aさん）自身のチェックイン（予定・タスク・質疑の全体）
- Eさんの KR 修正についてのCさんとのやり取り（19:00〜20:35）
- Eさんからの研修（情報セキュリティ・経理教育）の連絡
- Eさんの商品マスター支援の申し出、取引先Sの体制の話
- Dさんの体調の確認、終了後の雑談
- Cさん「当社がやっても全然刺さらないですよ」のような補足の言い回し

R の題名は「他社T生産方式と子会社YのAI意見交換」で、Cさんの2議題に焦点を当てている。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | 省く基準を明文化してプロンプトに入れる（例：記録者自身の報告、雑談、体調、研修連絡は省く） | 再現性がある | 基準を言葉にしきれない可能性がある |
| B | 過去の R を見本として複数渡し、取捨選択を真似させる | 言葉にしにくい感覚も伝わる | 見本の会議に引っ張られる。盲検の検証には使えない |
| C | AI は全部書いた「詳細版」を作り、人が削る | 抜けが起きない | 人の作業が残る。今と比べて楽になるか不明 |
| D | 詳細版と要約版の2つを作る | 用途で使い分けられる | どちらが正式な議事録か決める必要がある |

## 不明点（Aさんに確認したい）

1. Aさん自身のチェックインを書かないのは、記録者だからか、それとも内容が議事録に載せるほどでないからか。
2. KR 修正のやり取りや研修の連絡は、「書かなくてよい」のか「書き忘れ」なのか。
3. この議事録は誰が何のために読むか（例：上長への報告、後日の振り返り）。読み手によって省く基準が変わる。

## ソフトへの影響

- 取捨選択のルール（または見本）がプロンプトの中心になる。
- 検証計画の「網羅数」は、R が意図的に省いたものをキーポイントに入れるかどうかで結果が変わる。キーポイントの選び方もこの基準に合わせる必要がある。

## 決定内容

2026/11/23 Aさん：
- CI などの R は、意味があると思われるものだけを書いている。AI にはその判断はできないので、**AI は拾えるものをすべて拾う**（案 C に近い）。完全ではなくてよい。
- R と重なる部分は、R を正解として見直す。R にない記載は、発言に根拠があれば誤りとはしない。
- Word（R）は、Aさんが会議内容を正しく理解するためのもの（読み手＝Aさん本人）。
- 対応：検証計画 4.4 に評価の扱いを追記した。
