## 何が起きているか・何が分からないか

崩れた文字起こしを、Claude が【推定】を付けずに、もっともらしい一般語に置き換えた。検証計画の合格基準「無断推定 0件」に違反する。読み手は誤りに気づけないので、議事録として最も害が大きい種類の誤り。

## 根拠

| 文字起こし | C の記載（印なし） | 正しい内容（R） |
|---|---|---|
| 研修オペレーション | 受発注オペレーションに近い | 検収オートメーションのスコープ |
| 受発中心レス化、ジャパンチューシブレス | 受発注レス化 | 受発注シームレス化 |
| 今日ヒアリングした内容をちょっと分解して構造とかいただいても | 今日のヒアリング内容を分解・構造化したものが欲しい | 受発注シームレス化を先に検討するため、Bさんの資料が欲しい |

CI では無断推定は「家電リスト」（文字起こしそのまま）の1件だったが、Bさんヒアリングでは Claude 自身の言い換えで3件起きた。文字起こしが崩れているほど、Claude が「意味の通る文」に寄せてしまう。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | プロンプトで「文字起こしにない語を使ったら必ず【推定】」を徹底し、作成後に Claude 自身に文字起こしと照合させる（自己点検） | すぐできる | 自己点検でも見落としは残る |
| B | 議事録の各文に根拠のタイムスタンプを付けさせ、根拠の文と語が一致しない箇所を機械的に検出する | 漏れにくい | 出力が複雑になる。確認用の版でのみ使う |
| C | 用語集（ISSUE-005）を整備し、そもそも推定が必要な箇所を減らす | 根本的 | 用語集にない語では同じことが起きる |

推奨：A＋C。B は確認用の版（ISSUE-007）と合わせて検討。

## ソフトへの影響

議事録作成を「下書き → 文字起こしとの照合（自己点検）」の2段階にする。

## 決定内容

2026/11/23 対応（Claude）：案 A＋C を実施。
- 自己点検 `src/check_coverage.py` に「根拠のない語の点検」を入れた。議事録のカタカナ・英字の語のうち、文字起こしにも用語集にもないものを一覧にする（【推定】の印を付けた語は対象外）。
- 2会議の議事録で、印のない言い換え5件（「正解」→会議、「会期」→会議、「ビルコン」→ビルトイン、「反抗」→ハンコ、文字起こしにない「スコープ」）を検出し、【推定】を付けるか、文字起こしどおりに直した。
- 用語集（ISSUE-005）を整備し、推定が必要な箇所そのものを減らした。
