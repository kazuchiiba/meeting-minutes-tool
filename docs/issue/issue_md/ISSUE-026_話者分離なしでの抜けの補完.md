# ISSUE-026 話者分離をしない会議で、抜けの補完が働かない・補完でまた潰れる

| 項目 | 内容 |
|---|---|
| 区分 | 誤り |

| 対象会議 | 11/19 子会社X定例会 |
| 関連 | ISSUE-011（抜けの補完）、ISSUE-024（話者分離の既定は「しない」）、ISSUE-021（幻覚）、src/fill_gaps.py |

## 何が起きているか・何が分からないか

話者分離の既定値を「しない」にした後、最初に処理した 子会社X定例会（36.5分）で、文字起こしに2分程度の抜けが複数残った。原因は2つ。

1. **発話区間が分からない**：抜けの補完の「発話があるのに文字起こしがない区間を探す」処理は、pyannote の発話区間を使っていた。話者分離をしないと発話区間がなく、この検出が働かなかった（ISSUE-024 でも「pyannote なしだと補完で戻る文字が1/10」と確認済み）。
2. **補完でまた潰れる**：補完で長い区間（1〜2分）を一度に Whisper に渡すと、また数文字に潰れた。話者分離ありの場合は pyannote が発話を細かく区切っていたので起きにくかった。

## 根拠

- 最初の補完後の文字起こし：1:56〜3:48（約2分）、14:26〜16:05（約1.5分）などが空いていた。
- 発話区間を Silero VAD で求めて補完をやり直した後も、1:44〜3:49（125秒）が22文字、14:26〜16:09（103秒）が「承認されたら」の6文字、10:47〜11:15（28秒）が「はい」の2文字のままだった。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | 話者分離をしない場合は、Whisper 付属の Silero VAD で発話区間を求めて、pyannote の代わりに使う | 数秒で終わる。追加の環境が不要 | pyannote より発話区間の精度が低い可能性 |
| B | 補完では、発話区間を25秒以内の区切りにまとめて1つずつ文字起こしする（長い区間を一度に渡さない） | 潰れにくくなる。話者分離ありの場合にも効く | 区切りの境目で語が切れる可能性。処理回数が増える |
| C | 抜けが多い会議は「話者分離する」に切り替える | 実績のある方法 | 処理時間が大幅に増える |

## ソフトへの影響

`src/fill_gaps.py` の補完の方法が変わる。話者分離あり・なしのどちらでも、発話区間を細かく区切って補完する形になる。

## 決定内容

2026/11/23 Claude：A と B を実装（`fill_gaps.py`：話者分離なしでは Silero VAD の発話区間を使う。補完は `CHUNK_SEC`＝25秒以内の区切りごとに文字起こしする）。子会社X定例会で補完をやり直して効果を確かめる。正式採用はAさんの判断待ち。

## 追記（2026/11/24 話者分離ありとの比較）

同じ音声を話者分離ありで処理すると、pyannote の発話区間で補完でき、文字起こしの量が +25%（6,781字 → 8,442字）になった。話者分離なしで区切って再実行した補完の文字起こしには残っていなかった発言（10:23〜11:53 のDさんの説明、17:17〜17:33 のカットオーバーの質疑など）があった。一部は最初の補完版の文字起こしにはあった。**区切って再実行すると、発言が消えることがある。** 詳細は `docs/verification/20261119_子会社X定例会_話者分離の有無の比較.md`。
- 次の検討：話者分離しない会議でも、補完の区間検出だけ pyannote のセグメンテーション（②の最初の「区間検出」約1分）を使う案。声の特徴量（約44分）を計算しないので速い。

## 追記（2026/11/24 pyannote の区間検出だけを使う試行・採用）

- 試行：①の文字起こしを再利用し、`src/detect_speech.py`（pyannote の区間検出だけ）で発話区間を求めて補完した。区間検出は2.5分（426 区間）、補完は63分。文字起こしは 271 セグメント・8,473字（Silero VAD 版 6,781字、話者分離あり 8,442字）。話者分離なしで抜けていた発言（1:18〜1:56、10:23〜11:53、17:17〜17:33 など）はほぼすべて戻った。抜けが少なかったのは、話者の区切りではなく、pyannote の発話区間の検出の方が Silero VAD より良いためと考えられる。詳細は `docs/verification/20261119_子会社X定例会_話者分離の有無の比較.md`。
- 決定（2026/11/24 Aさんの承認）：話者分離をしない場合、`run_pipeline.py` が③の前に `detect_speech.py` を実行し、その発話区間で補完する。`setting.xlsx` の `gap_fill_vad`（pyannote / Silero、既定は pyannote）で選べる。`.venv-diar` がない・区間検出が失敗した場合は Silero VAD で続ける。テキスト＋音声の入力でも同じ。設計書 Ver0.11（5.3、5.4、6.1）。
