## 何が起きているか・何が分からないか

議事録の点検（⑤）は、書いた本人（Claude）と機械的なスクリプトだけで行っていた。書いた本人は自分の抜けや言い換えに気づきにくい。Aさんから、Agent を設定で使えるようにし、議事録を生成した後にレビューする Agent を作る案が出た。

## 根拠

- これまでの自己点検でも、点検スクリプトに言われて初めて気づいた言い換えがあった（ISSUE-014）。
- Claude の利用画面で「Give simple subagents a cheaper model」が改善策として示されていた（軽いモデルの Agent に単純な作業を任せる）。

## 選択肢

| 案 | 内容 | 良い点 | 懸念 |
|---|---|---|---|
| A | 書き手（Claude）とスクリプトだけで点検する（今まで） | 利用量が少ない | 書き手の見落としに気づきにくい |
| B | 議事録を書いていないレビュー Agent（軽いモデル）に、文字起こしと照らし合わせて点検させる。直すかは書き手が判断 | 独立した目で点検できる。軽いモデルで利用量を抑えられる | 文字起こしをもう一度読むぶん利用量が増える。軽いモデルの見落とし |
| C | 書き手とレビューを別の会社の AI にする（ISSUE-020） | 見落とし方が違うので補い合える | 契約・費用・社内ルールの確認が必要 |

## ソフトへの影響

- `.claude/agents/minutes-reviewer.md`（レビュー Agent の定義）、議事録作成スキルの手順5-2、`setting/setting.xlsx`「議事録作成」シート（`review_agent`・`review_model`）、`src/setting.py`（`review_agent`）。

## 決定内容

2026/11/24 Aさん：Agent モードを設定できるようにし、議事録を生成した後にそれをレビューする Agent を作る。
- 対応：B を実装。
  - `.claude/agents/minutes-reviewer.md`：読むもの（文字起こし・議事録・自己点検・会議情報・書き方のルール・用語集）と読まないもの（人手版・他の会議）、8つの観点（付け足し・印のない言い換え・確度の格上げ・抜け・発言者・用語・決定事項・書式）、報告書の形式（`evidence_log/<名前>_議事録.review.md`）を定義。議事録は直さない。
  - `setting/setting.xlsx`「議事録作成」シート：`review_agent`（使う / 使わない、既定「使う」）、`review_model`（sonnet / haiku / opus / 書き手と同じ、既定 sonnet）。
  - 議事録作成スキル 手順5-2：設定が「使う」ならレビュー Agent を呼び、指摘を確かめて直す。依頼文には書き手の判断を書かない。

2026/11/24 Aさん：レビュー Agent の既定は Sonnet、設定で Opus も選べるようにする。今後モデルが増えたときに追加・切り替えできるようにする。可能なら OpenAI の API も設定すれば使えるようにする。
- 対応：
  - `setting/setting.xlsx` に「モデル一覧」シート（名前 / 提供元 / 呼び出し名 / 使える / 説明）を追加。`review_model` は一覧から選ぶ。行を足せば新しいモデルを選べる。
  - OpenAI：`src/openai_review.py`（同じ指示・資料を chat.completions に送り、同じ形式の報告書を書く）。API キーは `.env`（.gitignore 済み）。openai パッケージを .venv に導入済み。モデル名は記録者が「モデル一覧」の openai 行に記入して「使える」にする（今は「使えない」）。
  - 議事録作成スキル 手順5-2：提供元が OpenAI なら `openai_review.py` を実行する分岐を追加。
- 試行の結果（子会社X定例会、sonnet）：高11 / 中13 / 低4。27件が正しい指摘で直した。直さなかったのは1件（製品名の英語表記）。スクリプトの自己点検では見つからなかった、付け足し（No.1〜6。古い版の文字起こしで議事録を書いていたのが原因）・数字の落ち（0.03）・決定事項の確度の格上げを見つけた。
- 残り：OpenAI での実行の確認（記録者が API キーとモデル名を設定してから）。利用量の比較。
