# ツール説明書（HTML）の作成・更新

**md は AI が読むもの、HTML は人が読むもの。** HTML はスクリプトが md・JSON を変換して組み立てるので、Claude は中身を読まない（コンテキストと時間を使わない）。

## いつ作るか

開発サイクルの**最後に1回だけ**作る。途中の工程（要件定義・実装・評価・Issue 起票）のたびには作らない。

## 手順

### 1. 元の md・JSON が最新か確かめる

HTML に取り込むのは次の4つ。古いまま作らないよう、先に更新しておく。

| 章 | 元のファイル | 更新に使うスキル |
|---|---|---|
| 設計書 | `docs/design/議事録作成ツール設計書.md` | （直接編集） |
| 詳細設計書 | `docs/design/design_detail/*.md` | `design-detail` |
| 評価（テスト結果） | `docs/verification/results/*.json`、`reports/*.md`、`*.md` | `verification` |
| Issue | `docs/issue/issue_md/ISSUE-*.md` | `issue` |

### 2. HTML を作る

```powershell
.venv\Scripts\python .claude\skills\tool-manual\scripts\build_manual.py
```

出力：`docs/ツール説明書.html`（外部のファイルや CDN を使わない1ファイル。オフラインで開ける）。

### 3. 記録者に伝える

HTML のパスを伝える。中身の説明は不要（記録者が HTML で読む）。

## HTML の構成

| 章 | 内容 |
|---|---|
| 概要 | Issue 件数（全体・未完了）、テスト結果の件数、詳細設計書の件数 |
| 設計書 | 設計書の全文 |
| 詳細設計書 | コードごとの詳細設計書（折りたたみ） |
| 評価（テスト結果） | テスト結果の一覧表、回ごとの報告・検証計画・比較資料（折りたたみ） |
| Issue | 状態の凡例、状態で絞り込める一覧表、各 Issue の内容（折りたたみ。一覧の ID から開く） |

## 注意

- 社内の部署名・人名を含むので、HTML を社外のサービス（Artifact の公開など）にアップロードしない。
- HTML を手で編集しない。直したいときは元の md を直して作り直す。
