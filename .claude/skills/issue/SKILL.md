# Issue 運用

論点・不明点を `docs/issue/issue_md/` に1件1ファイルで管理し、一覧は Excel で把握する。
**md ファイルが正本**で、一覧（`docs/issue/Issue一覧.xlsx` と `docs/issue/issue_md/README.md` の表）はスクリプトで生成する。一覧を手で編集しない。

## フォルダ構成

```
docs/issue/
  Issue一覧.xlsx         一覧（人が見る。ID・ファイル列から md を開ける。D1 に状態の凡例）
  issue_md/
    README.md            運用ルール + 一覧表（表はスクリプトが更新）
    _template.md         起票用ひな形
    ISSUE-001_題名.md    1件1ファイル（正本。AI が読み書きする）
```

`docs/issue/issue_md/` や `_template.md` がなければ、このスキルの [assets/](assets/) からコピーして作る。

## 起票する

1. `docs/issue/issue_md/` の既存ファイルから最大の連番を確かめ、次の番号を振る（欠番は埋めない）。
2. `_template.md` をコピーして `ISSUE-連番_短い題名.md` を作る。題名は名詞句で短く（例：`話者分離`、`確度の書き分け`）。
3. 各欄を埋める。
   - **区分**：要件 / 誤り / 論点 / 不明点 のどれか1つ
     - 要件：人手版などから読み取れる、成果物に求められていること
     - 誤り：AI の出力が要件や事実に照らして間違えていたこと
     - 論点：どうするか決める必要があること（仕様・運用）
     - 不明点：事実が分からず確認が必要なこと
   - **状態**：起票時は `未着手`
   - **根拠**：該当箇所を引用し、タイムスタンプやファイル名を併記する。推測で書かない。
   - **選択肢**：論点なら最低2案。良い点と懸念を両方書く。
   - **ソフトへの影響**：この Issue の結論で、作るソフトの何が変わるか。
4. 1つの Issue に複数の論点を混ぜない。混ざったら分割して相互に「関連」へ書く。

## 更新する

- 状態の変化：ファイル内の「状態」を書き換える（未着手 → 検討中 → 決定 → 済、または 保留）。
  - 決定：方針は決まったが、対応（実装・資料修正など）が残っている
  - 済：対応まで終わり、これ以上の作業がない。**Issue が終わったら必ず「済」にする**
  - ユーザーの回答だけで完結する Issue（確認・方針の決定のみで作業が発生しないもの）は、決定内容を書いてそのまま「済」にしてよい
- 決定したら「決定内容」に、日付・決めた人・決定内容・理由を書く。保留も理由を書く。
- 「済」にするときは、何をして終わったか（修正したファイル、反映先の Issue など）を決定内容に1行追記する。
- 回答から新しい要件・論点が出たら、既存の該当 Issue に追記するか、新しく起票して「関連」でつなぐ。
- ユーザーが決めていないことを「決定」にしない。Claude の推奨は「選択肢」の下に「推奨：」として書く。

## 一覧を作り直す

起票・更新したら、必ずプロジェクトルートで実行する。

```
.venv/Scripts/python .claude/skills/issue/scripts/build_issue_list.py
```

- `openpyxl` が必要（なければ `.venv/Scripts/python -m pip install openpyxl`）。
- Excel：「Issue一覧」シート（フィルタ付き、状態で色分け、ID・ファイル列が md へのリンク）と「集計」シート（区分×状態の件数）。
- `Issue一覧.xlsx` を Excel で開いている間は保存に失敗する。その場合はユーザーに閉じてもらう。

## 一覧を見せる

「どんな Issue がある？」などと聞かれたら、スクリプトの標準出力（ID・状態・区分・題名）を表にして返す。
個々の Issue を参照するときは `[ISSUE-001](docs/issue/issue_md/ISSUE-001_話者分離.md)` のようにリンクで示す。
