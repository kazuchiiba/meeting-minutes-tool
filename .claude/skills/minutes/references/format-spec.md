# 議事録の書式（固定仕様）

記録者が参考に示した人手版の議事録（2026/11/20 の2会議）の書式を、固定の仕様とする（docs/issue/issue_md/ISSUE-003）。
この仕様を変える場合は、記録者の指示を受けてから、このファイルとテンプレートを直す。

| 会議の種類 | 見本（人手版） | テンプレート |
|---|---|---|
| チェックイン | `INPUT/20261120_CI(他社T生産方式と子会社YのAI意見交換)_Ver0.1.docx` | [../assets/template_checkin.docx](../assets/template_checkin.docx) |
| ヒアリング | `INPUT/20261120_Bさんヒアリング_Ver0.1.docx` | [../assets/template_hearing.docx](../assets/template_hearing.docx) |
| その他 | （見本なし。ヒアリングの書式を使う） | template_hearing.docx |

テンプレートは見本をそのまま複製したもの。`src/make_docx.py --type <種類>` が本文を差し替えて使う。

## 1. ページ・文字

| 項目 | 仕様 |
|---|---|
| 用紙 | レター（21.59 × 27.94 cm）、余白 左右 3.175 cm・上 2.54 cm |
| フォント | Meiryo UI 10.5pt（標準スタイル） |

## 2. 冒頭の表（2列・罫線あり）

| 行 | 左の列 | 右の列 |
|---|---|---|
| 1 | （2列を結合）会議名 | |
| 2 | 日時 | `2026/11/20(金) 16:30-17:00` の形。時刻が分からなければ書かない |
| 3 | 場所 | 分からなければ空欄 |
| 4 | 参加者（敬称略） | `部署：氏名、氏名(記)` を部署ごとに改行。記録者に `(記)`。部署は用語集の「人名」シートから取る |
| 5 | 資料 | 分からなければ空欄 |

会議名・日時・場所・資料は、会議情報ファイル（`INPUT/<名前>.会議情報.txt`）の値をそのまま使う。会議名は記録者が決める（既定値は入力ファイル名）。

## 3. 本文の構成

```
【決定事項】
  ➢ 決定事項。(発言者)
【TODO】
  ➢ 内容（担当：氏名、期限：…）
【会議内容】
■ 見出し（太字・下線、番号付きリスト1段目）
  ➢ やり取りの最初の発言。(発言者)（リスト2段目）
     ✧ やり取りが一段落するまでの応答・続き。(発言者)（リスト3段目）
  ➢ 次のやり取りの最初の発言。(発言者)
     ✧ …
[(画像内容名)]（見出しの会話の最後。箇条書きにしない）
【AI作成メモ】
  ➢ 作成方法・話者対応表・注意事項
```

- 【決定事項】【TODO】は冒頭に置く（docs/issue/issue_md/ISSUE-009）。人手版にはない追加分。
- 【推定】【聞き取り不明】【要確認】は黄色の蛍光ペン（docs/issue/issue_md/ISSUE-007）。

## 4. 見出しの形

| 会議の種類 | 見出しの形 | 人手版の例 |
|---|---|---|
| チェックイン | `〇〇さんの会議/議題名` | `Cさんの会議/他社T生産方式の意見交換`、`Gさんの会議/交付決定通知書格納ツールのエラー` |
| ヒアリング | `取引先・対象/区分：内容`（区分＝確認・課題・懸念・活動・コメント） | `取引先P/課題：現場配送品で請求金額が丸め誤差で1円ズレる`、`取引先R/確認：取引先Rの請求書作成` |

区切り方と区分の使い分けは [writing-rules.md](writing-rules.md) の「2. 見出しの付け方」。

## 5. 発言の書き方

| 項目 | 仕様 | 人手版の例 |
|---|---|---|
| 発言者 | 文末に `(氏名)`、敬称略 | `…学びたいところは学びたい。(C)` |
| 文体 | 「である」調の書き言葉。発言者の一人称（私）は残してよい | `Nさんと私に落ちてきた。` |
| 質問 | 疑問文で書き、回答と交互に並べる | `Auth認証エラーはPythonでやっているのか。(A)` |
| 段落 | 1人の一続きの発言を1段落にまとめる | |
| 画像 | 画面共有の位置に `[(画像内容名)]` | 人手版は `[マニュアル]`。AI 版は `[(…)]` の形にする（docs/issue/issue_md/ISSUE-013） |
